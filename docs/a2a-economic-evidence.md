# Optional A2A economic evidence extension

Extension URI: `https://ecco.bot/extensions/economic-evidence/v1`. This URI identifies the draft profile; publishing these files does not deploy that URL.

Use the [A2A 1.0 Agent Card and extension mechanisms](https://a2a-protocol.org/latest/specification/). Add an entry to `capabilities.extensions` with `required:false` and `params.binding`. The binding is an `ecco.a2a-binding/v1` object signed by the accepted economic controller and includes entity, controller head, key, card URL, card digest, advertised service URL, relay URL, trust/evidence endpoints and expiry.

Compute `cardDigest` over the canonical card after excluding this extension entry and the card's separate `signatures` field. Normalize an absent extensions array to an empty array when authoring. Sign the complete binding minus `sig`. An independent client verifies the configured root, observed HTTPS card URL, digest, expiry, and a matching `supportedInterfaces` entry with `protocolVersion:"1.0"`. The root endorsement is only one direction of the binding; fetch the card from its authenticated service origin and validate entity/controller history independently. Copying a card to another URL does not establish ownership.

Discovery alone activates no economic guarantees. Requests and responses relying on the extension include its URI in `A2A-Extensions`. Existing A2A authentication, task lifecycle, transports, streaming, SDKs and the official CLI remain responsible for communication. Ecco links external task IDs and records attributable observations; a completed task does not automatically become buyer-accepted fulfillment.

The product includes authoring, verification and task-observation adapters. Its interoperability tests passed against official `@a2a-js/sdk` 1.1.0 (A2A 1.0 card resolution, binding preservation, HTTP+JSON message exchange and extension activation using a controlled transport) and the project Rust `a2acli` 0.1.11 (optional extension preservation during loopback card discovery). Ops also tests the separate [official standalone `a2a` CLI v0.2.0](https://github.com/a2aproject/a2a-cli/releases/tag/v0.2.0): optional extension discovery, REST negotiation, bearer/service headers and explicit extension activation. These bounded tests do not validate every transport or production endpoint. The Ops marketing site now builds the versioned documentation route. Publication of the reviewed site/core artifacts and a real partner-origin/authentication check remain release gates.
